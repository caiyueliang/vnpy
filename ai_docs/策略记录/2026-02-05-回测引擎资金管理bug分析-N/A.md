## 1. 问题描述

### 1.1 核心问题
回测引擎的资金管理逻辑存在严重bug，导致：
- 资金变成负数（如：-4,831,030,513.71元）
- 收益率计算异常（如：-483203.05%）
- 年化收益率计算为NaN

### 1.2 问题表现
1. **资金异常**：最终资金从1,000,000元变成-4,831,030,513.71元
2. **收益率异常**：总收益率显示为-483203.05%
3. **交易次数为0**：虽然订单执行了，但total_trades显示为0
4. **胜率为0%**：无法正确计算胜率

---

## 2. 问题分析

### 2.1 资金管理逻辑问题
回测引擎的资金管理逻辑存在以下问题：

1. **冻结资金逻辑错误**：
   - 开仓时将可用资金转为冻结资金
   - 平仓时将冻结资金转为可用资金
   - 但没有正确计算持仓盈亏

2. **余额计算错误**：
   - 余额计算公式：`balance = initial_capital + total_position_value - frozen - commission - slippage`
   - 当持仓市值计算错误时，余额会变成负数

3. **持仓盈亏计算错误**：
   - 持仓盈亏通过`(current_price - cost) * position_size`计算
   - 但持仓成本更新逻辑可能存在问题

### 2.2 绩效评估器问题
1. **daily_returns列表为空**：导致无法计算收益率
2. **trades列表为空**：导致无法计算胜率和盈亏比
3. **年化收益率计算为NaN**：因为daily_returns为空

## 4. 根本原因分析

### 4.1 资金管理架构问题
当前回测引擎的资金管理架构过于复杂，包含：
- balance（余额）
- frozen（冻结资金）
- available（可用资金）
- position_value（持仓市值）
- position_cost（持仓成本）

这些变量之间的依赖关系复杂，容易出错。

### 4.2 持仓盈亏计算问题
持仓盈亏的计算逻辑存在问题：
1. 持仓成本更新逻辑可能不正确
2. 持仓盈亏计算时机不对
3. 没有正确处理开仓和平仓的盈亏结算

### 4.3 绩效评估器数据收集问题
绩效评估器没有正确收集数据：
1. `daily_returns`列表为空
2. `trades`列表为空
3. 无法正确计算绩效指标

## 5. 解决方案建议

### 5.1 重新设计资金管理逻辑
建议采用简化的资金管理逻辑：

```
1. 使用单一资金变量：total_capital
2. 开仓时：total_capital -= trade_value
3. 平仓时：total_capital += trade_value + pnl
4. 持仓盈亏：通过持仓市值变化计算
5. 不使用冻结资金概念
```

### 5.2 修复持仓盈亏计算
1. 正确更新持仓成本
2. 在平仓时计算并结算盈亏
3. 将盈亏添加到绩效评估器的trades列表

### 5.3 修复绩效评估器
1. 确保daily_returns列表正确填充
2. 确保trades列表正确填充
3. 修复年化收益率计算逻辑
