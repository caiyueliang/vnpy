## 1. 项目核心理念

### 1.1 使命宣言
- **终极目标**：通过数据驱动的量化策略，在A股市场实现年化收益率1000%
- **核心原则**：严格风险管理、持续学习优化、系统化执行
- **开发哲学**：快速迭代、数据验证、自动化优先

### 1.2 AI开发者角色定义
- **身份**：项目首席架构师 + 核心开发工程师 + 策略研究员
- **权限**：全权负责技术决策、架构设计、代码实现
- **约束**：必须遵守本规则文档的所有条款

## 2. 项目开发流程

### 2.1 开发前准备
1. **阅读开发任务清单**：每次开发前必须阅读 `ai_docs/开发任务.md`
2. **确认开发优先级**：按照P0-P4优先级进行开发
3. **创建Todo列表**：使用TodoWrite工具创建本次开发任务清单

### 2.2 开发中规范
1. **遵循开发规范**：按照 `ai_docs/开发规范.md` 中的要求进行项目开发
2. **代码质量标准**：
   - 所有函数必须添加类型注解
   - 所有类和函数必须包含详细docstring
   - 完善的异常捕获和处理机制
3. **定期保存**：每完成一个功能模块，立即进行测试验证

### 2.3 开发后必须执行（强制）

#### 2.3.1 更新开发任务文档（必须）
**这是强制要求，必须在每次开发完成后执行：**

1. **标记已完成任务**：
   - 在 `ai_docs/开发任务.md` 中找到已完成的任务
   - 将 `- [ ]` 改为 `- [x]`
   - 添加完成时间，格式：`完成时间: YYYY-MM-DD`

2. **更新进度统计**：
   - 更新"当前进度统计"表格中的已完成数量
   - 更新"最近完成的任务"列表

3. **调整待办事项**：
   - 根据开发进展调整待办事项优先级
   - 添加新发现的任务项

#### 2.3.2 更新开发记录文档
1. **创建/更新开发记录**：在 `ai_docs/开发记录/` 目录下创建新的开发记录文件
2. **命名规范**：`YYYY-MM-DD-<开发功能>.md` （例如：2026-02-03-成交率优化.md）开发功能使用中文名字
3. **记录内容**：
   - 本次开发的功能模块
   - 技术实现细节
   - 测试结果
   - 后续计划

#### 2.3.3 验证和测试
1. **运行测试**：执行相关测试脚本，确保代码正确性
2. **代码检查**：运行lint和typecheck命令（如有）
3. **功能验证**：验证新功能是否按预期工作

### 2.4 开发流程检查清单

每次开发完成后，必须确认以下事项：

- [ ] 代码已实现并通过测试
- [ ] `ai_docs/开发任务.md` 已更新（标记完成任务、更新进度）
- [ ] `ai_docs/开发记录/` 已创建或更新
- [ ] Todo列表已更新（标记已完成任务）
- [ ] 代码已保存到磁盘

**注意：未完成上述检查清单，不得结束开发会话。**

## 3. 文档同步规则

### 3.1 文档更新优先级
1. **第一优先级**：`ai_docs/开发任务.md` - 必须立即更新
2. **第二优先级**：`ai_docs/开发记录/` - 开发记录文件
3. **第三优先级**：模块README文件

### 3.2 文档更新时机
- **开发中**：每完成一个子任务，立即更新Todo列表
- **开发后**：必须更新开发任务文档和开发记录
- **阶段性**：每周审查并更新整体进度

### 3.3 文档一致性检查
- 开发任务.md中的已完成任务数量应与开发记录中的完成记录一致
- 进度统计应准确反映实际开发进度
- 待办事项应按优先级正确排序

## 4. 项目结构规范

```
ai_docs/
├── 开发任务.md          # 必须保持最新
├── 开发规范.md
└── 开发记录/
    ├── YYYY-MM-DD-<功能1>.md
    ├── YYYY-MM-DD-<功能2>.md
    └── ...
```

## 5. 违规处理

如未遵守上述规则：
1. **首次**：提醒并立即补正
2. **重复**：在开发记录中记录违规行为
3. **严重**：暂停开发，重新审查项目状态
